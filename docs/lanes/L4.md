## Styling decision: plain CSS custom properties + one `nf-` stylesheet (not Tailwind, not CSS modules)

Why, in order of weight:

1. **L9's CSP is `style-src 'self'` with no `'unsafe-inline'`** (`scripts/csp-sri.mjs` fails
   the build on an inline `<style>`). Runtime style injection (CSS-in-JS) is therefore out;
   the shells must load a real stylesheet file with SRI. Inline `style={{}}` props are fine
   (React writes them through the CSSOM, which CSP does not govern) and are used only for
   computed geometry (bar widths, avatar hue).
2. **The two shells use different bundlers** — app-web is esbuild (spike S-B), app-desktop is
   Vite/Electron. Tailwind would have to run in both (`@tailwindcss/vite` is pinned; no
   esbuild/CLI path is), scanning `packages/ui` source from each shell's config; pixel
   identity would then depend on two scan configs agreeing. CSS modules would emit hashed
   class names per bundler and need each bundler to process ui's source, since `tsc -b`
   emits no CSS at all.
3. A hand-authored stylesheet with a stable `nf-` namespace is loaded verbatim by any
   consumer (`<link>` or `import './ui.css'`), so both shells get **byte-identical** CSS.
   Components never `import` CSS, so `dist/*.js` has no non-JS imports.

Consequence for the orchestrator: `@sovit/ui`'s `exports` map only has `"."`, so a shell
cannot `import '@sovit/ui/ui.css'` today. Please add (package.json is orchestrator-owned
beyond scripts):

```json
"./ui.css": "./dist/ui.css",
"./tokens.css": "./dist/tokens.css",
"./components.css": "./dist/components.css"
```

and have the package build run `npm run -w packages/ui build:css` after `tsc -b` (root
`npm run build` is `tsc -b` only, which does not produce the CSS). Until then a shell can
`@import` the `src/**/*.css` files by relative path — Vite and esbuild both resolve CSS
`@import`.

Tailwind 4 stays pinned and unused by this lane; nothing here prevents a later switch.

## Player contract (build-plan §6.2)

- `media` is a slot (`ReactNode`): the shell renders its own `<video>` (blob-server URL,
  service-worker URL or MSE) and the player draws chrome around it. No playback or network
  code here; `ref` on the outer element lets the shell call `requestFullscreen()`.
- `state: PlayerState` is owned by the screen; every control emits a `PlayerAction`
  (`toggle-play`, `seek {toSec}`, `set-volume`, `toggle-mute`, `set-rate`, `set-rendition
  {label}`, `toggle-captions`, `toggle-pip`, `toggle-theater`, `toggle-fullscreen`,
  `toggle-mini`, `toggle-peers`, `close`, `play`, `pause`). `seek` targets are already clamped.
- Seek bar layers: buffered ranges (`buffered`), **paid so far** (`paidThroughSec`, orange),
  played (accent), thumb; an invisible native `<input type=range>` on top carries the
  slider semantics (`aria-valuetext` "1:40 of 10:00").
- Keyboard (`keyboard.ts`, pure): space/k, j/l ±10 s, f, m, t, i, `<`/`>` speed through
  `[0.25 … 2]`, 0–9 seek N×10 %. Extras in the same idiom: ←/→ ±5 s, ↑/↓ volume ±5 %, c
  captions, p PiP, Home/End. Ctrl/Alt/Meta chords and text-entry targets are ignored;
  arrow keys on the native range inputs are left to the browser. The region itself is
  focusable (`tabIndex=0`); the shell may also route `document` keydowns through
  `keyboardAction(ev, state)`.
- Modes: `mini` (compact 400 px chrome with title, expand, close — the shell decides where
  it floats), `theater` / `fullscreen` (class + pressed icon only; the shell owns layout and
  the Fullscreen API), `pip` (pressed icon; the shell calls `requestPictureInPicture`).
- Every control has an accessible name (`aria-label`, `aria-pressed` for toggles,
  `role=menu` / `menuitemradio` for quality and speed, `aria-live` status text).
- Controls auto-hide after `autoHideMs` (default 3000) while playing; stories use 0.

## Markdown subset

`parse.ts` tokenises: `**bold**`/`__bold__`, `*em*`/`_em_` (underscores only at word
boundaries), `[text](https://…)`, bare `http(s)://` URLs (trailing punctuation dropped),
`nostr:npub1…|nprofile1…|note1…|nevent1…|naddr1…` (bare or as a link target), `\n` → `<br>`,
blank line → paragraph. Anything else — every `<`, `&`, `javascript:`, `data:`, relative or
protocol-relative target — is literal text. Links render `target="_blank"
rel="noopener noreferrer"`; `nostr:` refs go to the `renderNostr(ref)` slot (the screen
resolves the profile through `NetworkAdapter.profile` and returns a chip), defaulting to a
neutral text chip with no `href`. Input is capped at 20 000 chars (`maxChars`) so pathological
comments cannot make the O(n·k) delimiter scan expensive. The test greps every component
source for `dangerouslySetInnerHTML`/`innerHTML`/`insertAdjacentHTML`/`outerHTML`.

## Assumptions and things I was unsure about

- **Thumbnails/avatars are passed in as resolved URLs** (`thumbnailSrc`, `avatarSrc`). The
  build-plan's "verify `x` hash before display" is `NetworkAdapter.image(url, sha256)`, which
  is a screen (L5) concern — a presentational card must not call the adapter. The card still
  reads `Rendition.placeholder` (the inline data URL) itself for blur-up.
- **VideoCard price = cheapest rendition total**, "from" when they differ. The alternative
  (sats/min at the default rendition) is one prop away — `renditionRatePerMin` exists — if
  Cameron prefers a rate on cards.
- **Player `paidThroughSec`** is my reading of "paid so far" for the seek bar: the screen
  converts blocks paid → seconds (blocks × blockSize / bitrate). The in-chrome chip shows
  `spend.ratePerMin` and total from `PlaySession.onSpend`.
- **Sheet/Toast positioning**: `position: fixed` by default with an `inline` prop for
  Storybook/embedding. Mini-player is NOT fixed — the shell decides where it floats.
- **`data-theme` on `<html>`** is the override hook (ADR 0005 Settings toggle). If the shells
  prefer an attribute on a wrapper element, `applyTheme(pref, element)` takes any element,
  but `tokens.css` targets `:root[data-theme]`; say so and I will widen the selector.
- **`.storybook/`, `*.stories.tsx` and `scripts/`** are outside `packages/ui/tsconfig.json`.
  `scripts/tsconfig.json` (new, under my allowlist) makes the ESLint projectService
  type-check the scripts with the repo's strict rules; stories/.storybook stay on the
  non-type-aware set per the orchestrator's note, but are written to the same standard
  (no `!`, explicit types on the decorator).
- **Node runs the scripts' TypeScript directly** (`node scripts/screenshots.ts`, Node 22.22
  type stripping). No ts-node/tsx needed.
- **Fixture observation for the orchestrator (not my lane):** `packages/core/src/mocks/fixtures.ts`
  `fakeHex64` collides — `asPubkey('orbital') === asPubkey('kilnfire')` and
  `asPubkey('lowtide') === asPubkey('greenroom')`, so `CHANNELS[0]`/`[1]` and `[2]`/`[4]` share a
  pubkey and any lookup by `video.author` is ambiguous (stories show "Orbital Mechanics" on a
  Kilnfire video). Cosmetic here; L5 screens that key maps by pubkey will hit it.
- Tailwind 4 and `@tailwindcss/vite` are pinned but unused (see the styling decision).
  `react-docgen` is turned off in Storybook (`typescript.reactDocgen: false`) — controls are
  not needed for state stories and it avoids a TS parse of `.storybook`-external files.
- `storybook build` warns that the preview chunk is > 500 kB; that is Storybook's own runtime,
  not our code.

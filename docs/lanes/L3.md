# Lane L3 — gateway (`packages/gateway/`)

**Issued against `CONTRACTS_VERSION = 3`** (`packages/core/src/contracts/version.ts`, ADR 0004).
Date: 2026-09-05. Branch `lane/L3`. No contract change requested
(`docs/contract-requests/L3.md` does not exist on purpose).

## What was built

`@sovit/gateway` = `@sovit/seeder` plus (build-plan §5): a WS bridge (one WebSocket = one
Hypercore replication stream + `pay/1` mux), Blossom HTTP (BUD-01/02/04/06/09) served from
the seeder's sha256 → blob index, an upstream payer (the gateway as a viewer, `range.core`
on every `PAY`), a validated JSON config, T11 hardening on the HTTP/WS side, and the
`dist/index.js --config` entry the canonical systemd unit already points at.

Nothing in this package implements hashing, signatures, blinding or key derivation.
sha256 for BUD-02 is `node:crypto` `createHash` (`http/body.ts`); Merkle verification is
Hypercore's; Noise is `@hyperswarm/secret-stream`'s; kind-24242 / kind-1984 signature
checks are Stage 2's behind the `BlossomAuth` interface. `ReportStore` records
`signatureVerified: false` on every report so nobody mistakes stored reports for verified ones.

## Public API / config surface

### For L7 web-shell (the browser)

- **WebSocket endpoint**: `ws(s)://<host>/<ws.path>` (default `/ws`). Binary frames only —
  a text frame destroys the connection. Wrap the socket as a Duplex, pipe into
  `core.replicate(true)` / `store.replicate(true)` (browser = Noise initiator, exactly the
  S-B rig; `src/ws/ws-duplex.ts` is the Node twin of the browser adapter). Corestore-level
  replication is what the gateway runs, so many cores share one socket.
- **The gateway is a seeder**: after the Noise handshake the seeder admits the session
  (ban list → rate limits), serves blocks, and cuts a non-payer at `windowBlocks + 1` via
  the synchronous `upload` gate. It sends `HELLO` with `satsPerBlock =
  ceil(policy.satsPerBlock × (100 + markupPercent) / 100)`, `acceptedMints`, `split`, its
  `p2pk`. Pay it with `PAY{range.core,
  fromBlock, toBlock, …}` at that price; it ACKs through the seeder's pay bridge.
- **Blossom** (BUD-01 status codes; `Access-Control-Allow-Origin: *` on everything):
  - `GET|HEAD /<sha256>[.ext]` → 200 / 206 (`Content-Range`, `Accept-Ranges: bytes`,
    `Content-Length`, `Content-Type` from the CAS entry mime or `application/octet-stream`,
    `ETag "<sha256>"`, immutable cache headers) / 404 / 416 (`Content-Range: bytes */size`).
    Suffix ranges honoured; multi-range and non-`bytes` units ignored → 200 full (RFC 7233
    §3.1). `DELETE` → 405 (BUD-12 is not vendored; deletion is an operator action).
  - `PUT /upload` (`Content-Length` required → 411; `X-SHA-256` optional → 409 on mismatch,
    400 if malformed; `Content-Type` → 415 if not in `blossom.allowedMimeTypes`; over
    `http.maxUploadBytes` → 413 from the header or mid-stream; `Authorization: Nostr …`
    verified by `BlossomAuth` with verb `upload` + the hash — BEFORE the body when
    `X-SHA-256` is present, after hashing otherwise) → 201 / 200 + Blob Descriptor
    (`url` = `blossom.publicUrl/<sha256>.<ext>`). 503 when no `BlossomAuth` is wired.
  - `HEAD /upload` (BUD-06): `X-SHA-256`, `X-Content-Length`, `X-Content-Type` → 200 / 400 /
    411 / 413 / 415 / 507. No token consumed unless `blossom.authHeadUpload: true`.
  - `PUT /mirror` (BUD-04): off by default; needs `blossom.allowMirror` + the origin host in
    `blossom.mirrorAllowedHosts` (exact `host[:port]`); sha256 = last 64-hex path segment
    (BUD-03 rule); verb `mirror` through `BlossomAuth`; fetched via the injected
    `mirrorFetch` (no default — the package ships no outbound fetch; wire `fetch` in the
    provider seam); 409 on hash mismatch, 502 on origin failure.
  - `PUT /report` (BUD-09): body = kind-1984 event with `x` tags; it is passed to
    `BlossomAuth` as verb `report` with the first hash (`Nostr <base64(event)>` is the only
    header shape the interface takes — see "unsure"); stored append-only, capped at 10 000.
  - `GET /list/<pubkey>` (BUD-02): descriptors of blobs that pubkey uploaded/mirrored HERE
    (the CAS index has no owner; `OwnerIndex` is the side table).
  - Every 4xx/5xx carries `X-Reason` (fixed strings; never a token, header or value).
- **Library** (`import { … } from '@sovit/gateway'`):
  `Gateway.create(config, deps)` / `listen()` / `close()` / `price()` /
  `openUpstreamCore(key)` / `setUpstreamPolicy(core, policy)` / `stats()`; `validateConfig`,
  `parseConfigText`, `applyEnvOverrides`, `gatewayPrice`, `gatewayPolicy`; `WsDuplex`,
  `WsBridge`, `BlossomHandler`, `resolveRange`, `UpstreamPayer`, `helloPolicyResolver`,
  `spoolToFile`/`readTextBody`; `main`, `parseCliArgs`. `GatewayDeps` = `{ seederEngine,
  viewerEngine, auth | null, payProtocol: (session) => PayProtocol | null, identity:
  { signChallenge }, fs?, crypto?, logger?, now?, mirrorFetch?, upstreamPolicy? }`.

### systemd entry-point confirmation

`deploy/systemd/nutflix-gateway.service`'s
`ExecStart=/usr/bin/node --jitless /opt/nutflix/packages/gateway/dist/index.js --config /etc/nutflix/gateway.json`
**is right as written** — `package.json` `main` is `./dist/index.js`, it self-runs only
when it is the process's main module (`isMainModule`, symlinks resolved), `--config` is the
flag, and `Type=simple` fits (`sdNotify` is a no-op without `NOTIFY_SOCKET`). `--jitless`
is compatible: nothing here uses WebAssembly. SIGTERM/SIGINT/SIGHUP → one graceful
`Gateway.close()` (pays owed upstream, drops sockets, closes the seeder, exits 0; hard
exit 1 after 25 s, under `TimeoutStopSec=30s`). `StateDirectory=nutflix-gateway` works
unchanged because `STATE_DIRECTORY` fills `dataDir`. Exit 78 (`EX_CONFIG`) on a bad config
or — today — on missing providers, so a misconfigured unit fails fast under
`Restart=on-failure` + `StartLimitBurst=5` rather than looping.

**What the orchestrator should change (cannot edit deploy/):** nothing in `ExecStart`.
Two notes for the README: (1) the gateway needs `Environment=NUTFLIX_GATEWAY_PUBLIC_URL=`
(or `blossom.publicUrl` in the JSON) set to the proxy's public origin, or descriptor `url`s
point at `http://127.0.0.1`; (2) `http.trustProxy: true` in the JSON when — and only
when — the listener is only reachable through the proxy, otherwise `X-Forwarded-For` lets
a client choose its rate-limit bucket. No `renderSystemdUnit()` is shipped: a byte-exact
renderer of a file I cannot edit would just be a second copy to drift (per the brief's
rule I omitted it and assert the ExecStart contract read-only in `cli.test.ts` instead).
The seeder's `renderSystemdUnit()`/`HARDENING_DIRECTIVES` and the canonical file already
disagree (`AF_NETLINK`, MDWE, `Type=notify` vs `simple`) — that reconciliation is the
orchestrator's listed L2 follow-up, not mine.

**TLS / proxy header expectations.** The gateway never terminates TLS. Put the proxy on
`443`, forward `/`-rooted paths unchanged (Blossom endpoints MUST live at the root —
BUD-01), pass `Upgrade`/`Connection` for `ws.path`, disable proxy request buffering for
`PUT /upload` (multi-GB bodies; the gateway enforces its own byte cap + 30 s idle timeout),
raise the proxy's body limit to ≥ `http.maxUploadBytes`, and forward `Range` untouched.
The gateway reads `X-Forwarded-For` (first hop) only with `trustProxy`; it never reads
`X-Forwarded-Proto` (descriptor URLs come from `publicUrl`). `_headers.txt` from
`scripts/csp-sri.mjs` belongs on the proxy serving the web build, not here.

## Assumptions and decisions (please read)

- **`hypercore-blob-server` read, not embedded.** Its `_onblob()` owns a listener, addresses
  blobs by `?key=&blob=&token=` and can only be used via `getLink()`; the range logic is
  ~15 lines. Reproduced in `blossom/range.ts` with two deliberate differences: suffix
  ranges (`bytes=-500`) are honoured per RFC 7233 (blob-server rewrites them to `0-500`),
  and `start === size` is 416 (blob-server's `start > length` check lets it through). The
  package stays a dependency for L6/L7 (its `imports` map is what makes it Bare-portable).
- **`streamx` is imported directly** (`ws/ws-duplex.ts`) though it is only a transitive dep
  (via hypercore, lockfile 2.28.1). The Hypercore side of the pipe IS a streamx stream; a
  `node:stream` Duplex would need a shim for nothing. If the orchestrator prefers an
  explicit pin, add `streamx@2.28.1` to `packages/gateway/package.json` — I may not touch
  the lockfile, and a `dependencies` entry without a lockfile change is worse than none.
- **Cut semantics over a socket.** The seeder destroys the Noise stream inside `upload`;
  the streamx pipeline destroys the `WsDuplex`, which sends a close frame (not
  `terminate()`), so frames already handed to the socket still reach the viewer. Result
  (asserted): engine records exactly `window + 1`, the viewer holds `0 < n ≤ window`
  blocks, the socket closes, the Noise key is persisted-banned. Same numbers as L2's wire
  rig; the direct-pipe "exactly window" is not reproducible over a real socket (L2's
  findings 1–2 apply verbatim to `ws`).
- **Upstream paying batches.** `onDownload` is synchronous; the pay runs on a microtask,
  so blocks that land in one tick are paid as ONE `PAY` for the whole contiguous run.
  `payEveryBlocks` is a lower bound per PAY, not a chunk size. Tails shorter than it are
  paid at `flush()` / `close()`. The unit test originally encoded "exactly N per PAY"; that
  expectation was wrong and was rewritten to assert exact coverage (0..n-1 once, `core` on
  every PAY, spend = blocks × price). Likewise `skippedNoPolicy` counts pay *attempts*
  skipped (the block stays pending, payable once a policy appears), not blocks. Also on
  HELLO the payer no longer force-pays sub-window runs (that was a real interplay bug: a
  HELLO landing in the same tick as the first `download` paid `[0,0]`).
- **Mint choice** when paying upstream: the seeder's FIRST listed mint that the gateway
  can pay with (`config.acceptedMints`), not the gateway's first — the seeder ordered them.
- **Provisional identity / `rebind`.** The gateway does not call `recordUpload` or
  `rebind` itself: all downstream accounting is the seeder's `PeerSession` (the brief says
  do not patch it). The seeder still uses the replay path (`recordUpload(pubkey, n)` on
  bind, no core) — see "seeder v3 re-issue" below. The engine the gateway hands the seeder
  is a v3 `PaymentEngineSeeder` (mock today), so the moment the seeder calls `rebind` and
  passes `core`, nothing in the gateway changes.
- **`PUT /upload` dedupe + cap are decided in the handler BEFORE `seeder.putFile`.** Found
  by test: `BlobStore.putStream` opens its second `source()` read stream eagerly and never
  consumes it on the dedupe / disk-cap early returns; the handler had already unlinked the
  spool file, so Node raised an uncaught ENOENT from the orphaned `createReadStream`. Not
  patched in the seeder (not my directory) — worth a one-line fix there (open the second
  stream lazily). Flagged for the L2 re-issue.
- **Over-cap bodies.** Node's `request.destroy()` on a 413 kills the response too ("socket
  hang up" client-side). The body readers `pause()` instead and every error reply sends
  `Connection: close`, so the client sees the 413 and the socket is dropped after it.
- **Kind-1984 reports go through `BlossomAuth` as verb `report`** with a synthetic
  `Nostr <base64(event)>` header — the interface's `reason` enum already has `wrong-kind`,
  so Stage 2's implementation can accept kind 1984 for that verb without a contract
  change. Structural checks (kind, pubkey hex, sig/id present, ≥ 1 `x` tag) happen first
  so junk never reaches the verifier.
- **No `PayProtocol` factory = sessions run without `pay/1`**: the seeder still serves and
  still cuts at the window. The CLI refuses to start without providers (exit 78) so this
  state is test-only, plus `--dev-mocks`.
- **`--dev-mocks` is the one flag-gated import of `@sovit/core` mocks from a runtime path**
  (execution plan §0 rule 4 says mocks are never on production paths). It is loaded
  dynamically only behind the flag, logs a `warn` line on every start, and its
  `BlossomAuth` stand-in accepts everything WITHOUT partial verification — anything
  smarter would be an auth implementation outside the locked dir. **Loopback fence
  (orchestrator review):** `--dev-mocks` refuses to start (exit 78, `reason:
  'dev-mocks-requires-loopback'`, host logged) unless the EFFECTIVE `listen.host` — after
  env overrides — is loopback: `127.0.0.0/8`, `::1` / `[::1]`, `localhost`
  (`isLoopbackHost` in `config.ts`, pure, exported). The check runs BEFORE
  `dev-mocks.js` is imported, so a `0.0.0.0` / LAN listener never even loads the mocks.
  Flagging the flag itself for review; if the orchestrator wants it gone, delete
  `cli/dev-mocks.ts` and the branch in `main.ts`.
- **Blossom `GET` never waits for the network beyond what `createBlobReadStream({wait:
  true})` does**; a blob in the index whose blocks are not local (a replica the gateway is
  still pulling) streams as blocks arrive. There is no per-request deadline on that — the
  socket idle timeout (60 s) is the backstop.
- **HTTP rate limiting reuses the seeder's `RateLimiter`** keyed by client address
  (global concurrency = `maxStreams`, per-client = `maxStreamsPerKey`, sliding window =
  `connectsPerWindow`/`windowMs`), so T11 has one implementation. WS upgrades count in it
  too, then hit the bridge's own `ws.maxConnections`, then the seeder's stream cap.
- **Logs.** Every line goes through `@sovit/seeder`'s `createLogger` (redaction in front);
  `no-console.test.ts` greps `src/` with no exemptions. Config errors, auth rejections and
  body failures log fixed reason strings. Asserted: a rejected upload's token bytes appear
  in neither the response nor the captured log; proof secrets from upstream PAYs never
  appear in the payer's log.
- **Deps:** none added. `@types/ws` was already pinned; `streamx` types come with the
  package. `types/holepunch.d.ts` duplicates the seeder's ambient file (its `src/types/` is
  not emitted into `dist/`, so every consumer of `@sovit/seeder`'s `.d.ts` needs the same
  module shapes) plus `userData` on the Noise stream — the protomux handle `pay/1` attaches
  to. Suggest the orchestrator move that file into `@sovit/core` or ship it from the seeder.

## Things I was unsure about

- **Q4 markup shape — RESOLVED (ADR 0005, percentage).** L3 originally shipped a flat
  per-block markup (`markupSatsPerBlock`, default 0) added to `policy.satsPerBlock`. Cameron
  chose a percentage; the `L3-markup` follow-up below replaced it with `markupPercent`
  (integer ≥ 0, default 0) and `ceil` rounding. `HELLO` still discloses the resulting price
  and the embedded seeder still verifies downstream `PAY`s against the marked-up policy — a
  config-schema change only, not a contract change.
- **Q8 (web-upload transcoding)**: not touched. `PUT /upload` stores bytes verbatim
  (BUD-02 "MUST NOT modify the blob"); `allowedMimeTypes` is the operator's lever.
- **`PRICE` has no core** (v2 shape): a `PRICE` from an upstream peer applies to every core
  on that connection from `effectiveFromBlock` on. Per-core prices need `core` on `PRICE`
  too — noting, not requesting (the Stage 2 codec bump is the place).
- **`/report` verb**: `BlossomVerb` has `report`, but BUD-09's body is a kind-1984 event,
  not a kind-24242 token. I pass it as the header; if Stage 2 would rather receive the raw
  event, the interface needs a second method — Stage 2's call.
- **`list` scope**: BUD-02 delegates `/list` to BUD-12 (not vendored), which requires a
  `list` auth token. I serve it unauthenticated (public descriptors of public blobs, hashes
  only) — flip to `authorize(…, 'list', null)` if the orchestrator wants BUD-12 strictness.
- **Whether the Gateway should own `PayProtocol` construction** — I went with an injected
  factory (`deps.payProtocol(sessionInfo)`) and the gateway calls `attach(mux)` on the
  connection's protomux (`noiseStream.userData`). Mirrors L2's "attach whoever constructs
  it" stance.

## What the seeder's v3 re-issue must change for me (docs/status.md follow-up)

1. **`PeerSession.onUpload` → `engine.recordUpload(accountId, 1, coreKeyHex)`** — the core
   is already an argument, it is just not forwarded. Until then the mock's per-core
   `range-not-uploaded` check cannot fire for downstream WS peers: the gateway's viewers
   pay with `range.core` set, and the mock falls back to the aggregate count. Money-path
   hole across cores on a multi-video gateway (ADR 0004 (c)); the gateway is THE case.
2. **`bindPubkey` → `engine.rebind(noiseKeyHex, pubkey)`** instead of `recordUpload(pubkey,
   replay)`. With (1) the replay cannot carry the per-core breakdown at all; and today the
   stale provisional window stays in `engine.windows()` (visible in `Gateway.stats()`
   consumers). `rebind` merge semantics (sum, ban sticks, sync `onWindowExceeded`) are
   already what the seeder's belt-and-braces `onWindowExceeded` subscription expects.
3. **Reject a core-less `PAY` as `malformed` when the stream replicates > 1 core**
   (contract text). The gateway always has ≥ 2 cores per session once it mirrors anything,
   so a v2 browser client that omits `core` should be refused, not silently verified
   against the aggregate.
4. **Resolve the policy per `range.core`** in the pay bridge (`policy: (core) =>
   PricePolicy`). `Seeder.setPolicy` is one policy per seeder; the gateway's per-core
   upstream policies (`config.upstream.policies` / `setUpstreamPolicy`) have no downstream
   counterpart until this exists — today every downstream core is priced at the gateway's
   single marked-up policy.
5. `BlobStore.putStream`: open the second `source()` lazily (see the ENOENT note above).
6. `Seeder.replicate()` is the right seam for the WS bridge and needed no change. A
   `session-open` payload that includes the protomux (or a `PeerSession.mux` getter) would
   remove the `noiseStream.userData` reach-through in `gateway.ts`.
7. `renderSystemdUnit()` vs `deploy/systemd/`: the orchestrator's listed reconciliation.

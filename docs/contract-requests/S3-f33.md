# Contract request — S3-f33 (against `CONTRACTS_VERSION = 6`)

**Status: a note, not a blocker.** Lane S3-f33 (F33, issue #8) ships against v6 and designs
around the gap below. Nothing here needs to land before the merge.

## What is missing: the seeder's own count in `ACK`

A viewer now keeps each seeder within its unpaid window by counting, per seeder, what it may owe
(`SeederCredit`, `OnePeerRouter`). Three kinds of block can only be ESTIMATED, because the viewer
cannot see what the seeder counted:

| Case | What the seeder counts | What the viewer can know |
|---|---|---|
| A request cancelled after it went out (a failover from a stalled peer; a `get` timeout on the gateway) | the block if it had already sent it | nothing: hypercore drops a late answer to a cancelled request |
| Requests in flight when a connection dropped | the ones it had sent | nothing |
| A PAY sent but not ACKed when a connection dropped | the PAY if it verified it before the drop | nothing |

The viewer must not overrun a window, because an overrun means a cut and a persisted ban. So each
of these counts against that seeder for good: a debt for the life of the worker or gateway,
remembered across reconnects. That is safe, but an honest seeder with a flaky link can end up
unusable for the session even when it counted none of them.

## Suggested addition (v7, whenever convenient)

```ts
// contracts/pay-protocol.ts
export interface AckMessage {
  readonly type: 'ACK';
  readonly core: CoreKeyHex;
  readonly fromBlock: number;
  readonly toBlock: number;
  readonly ok: boolean;
  readonly reason?: RejectReason;
  /**
   * v7: the seeder's `PeerWindow` for this viewer AFTER this PAY: `outstanding` (uploaded − paid,
   * summed over cores) and `windowBlocks` (its effective window). The viewer re-bases its estimate
   * on it; it only ever SHRINKS the viewer's debt estimate. A seeder that under-reports is asked
   * for more and then has to cut the viewer itself: its own fault, the same as announcing a
   * `windowBlocks` it does not honour. A seeder that over-reports gets fewer requests.
   */
  readonly window?: { readonly outstanding: number; readonly windowBlocks: number };
}
```

The codec (`core/src/pay-protocol/codec.ts`, locked) would carry two uints behind a flag. The
engine already computes the value in `verify` (`PeerWindow`).

## How S3-f33 designs around it

- `OnePeerRouter.debt(remote)` counts cancels after sending (`wireCancel.tx`) and requests lost
  with a connection. `SeederCredit` counts rejected PAYs and blocks owed at a link drop.
- A seeder that comes back under a new Noise key with the same signed HELLO pubkey inherits its
  old links' debts.
- The residual (honest seeders losing budget) is recorded in
  `docs/reviews/2026-09-25-pre-push-f33-one-peer.md`.

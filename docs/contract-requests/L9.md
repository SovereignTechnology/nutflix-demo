# Contract change request — lane L9 (ci-hardening)

Issued against `CONTRACTS_VERSION = 2`. Nothing in this lane is blocked on the request;
it is a follow-up for the orchestrator so the constant lives where the contracts say it
must.

## Request: a `NostrKind` entry for the release-hash event

**Where:** `packages/core/src/contracts/nostr.ts`, `NostrKind` ("Event kinds used by the
network. Single source of truth; do not scatter literals.")

**Why:** build-plan §7 says "release hash published in a Nostr event from the org key".
`scripts/reproducible-build.mjs` now emits that event as an unsigned template, and it
needs a kind. There is no release/build kind in `NostrKind` today, so the script takes
`--kind` and defaults to **30063**. That literal is scattered by definition; the lane
cannot add it to the frozen contracts, so this request asks the orchestrator to.

**Proposed addition:**

```ts
  ReleaseNotice: 30063, // addressable (NIP-01 30000–39999); `d` = app id, `x` = sha256 tree hash
```

**Shape the script emits** (so the constant and the consumer agree):

- addressable event, `tags`: `['d', '<app id, e.g. nutflix-web>']`, `['x', '<sha256 hex of the dist tree>']`,
  `['files', '<n>']`, `['size', '<bytes>']`, optionally `['version', …]`, `['commit', …]`, `['r', <url>]`…
- `content`: human-readable summary including the exact coreutils one-liner that reproduces the hash
- `id`, `pubkey`, `sig`: **empty** — filled by the offline signer with the org key

`x` follows the sha256-hex convention already used by NIP-92 `imeta` and Blossom BUD-01,
both vendored; the kind number itself is **not** backed by a vendored NIP (30063 is, from
memory, the "software release" kind of a NIP that is not in `docs/vendor/`, and that memory
is not to be trusted per §0 rule 6). If the orchestrator prefers a different number in the
addressable range, the script's `--kind` default and this file are the only two places to
change.

**Consumers once it exists:** L7 (web shell) should verify the served bundle's hash against
the latest `ReleaseNotice` from the org pubkey and say so in the UI (T13: "not fully fixable
in a browser — say so").

## Tests (190, all offline — no sockets, no network)

- `manifest/__tests__/manifest.test.ts` (44): **every fixture in `mocks/fixtures.ts` round-trips** `build → sign → verifyVideoEvent` with `toStrictEqual` (only `id`/`author`/`event` differ, as they must); the built tags with our extra imeta keys stripped equal the fixture's `event.tags` exactly. Rejections: tampered content/tags (`bad-signature`), non-event input, `wrong-kind`, `missing-tag` for title/mint/price/p2pk/imeta, imeta without `x` / malformed `x`, six malformed `hyper://` shapes, per-rendition error index, bad split/price/p2pk. Extras: captions, storyboard, non-zero `byteOffset`, non-default block size, `alt`, derived labels.
- A tampered-event-is-dropped test exists for **each read path**: `query`, `subscribe`, profiles (single + batch), follows, channel set, generic set, watch-later (private, proving the forged ciphertext never reaches `nip44Decrypt`), every video feed + search + `fetchVideos`, subscriptions feed, live video watch, trending (forged nutzap **and** forged video), comments, reply watch, reactions, 10019, 10002.
- `nostr/__tests__/event.test.ts` proves the `nostr-tools` verified-symbol cache trap: `verifyEvent({ ...verified, content: 'evil' })` returns **true** (spread copies the symbol); `verifyIncoming` returns `null`.
- `nostr/__tests__/no-key-material.test.ts` statically scans all non-test source in `nostr/` and `manifest/` for `generateSecretKey`, `finalizeEvent`, bare `getPublicKey(`, `nostr-tools/nip44|nip04|nip06|nip49`, `@noble`, `@scure`, `nsec`, `secretKey|privateKey|privkey`, `sha256(`, `schnorr`, `createHash`, and asserts `event.ts` is the only importer of `nostr-tools/pure`.
- `TestSigner` (test-only) records every call; it signs for real (so `verifyEvent` is exercised) but its `nip44*` is a reversible non-crypto transform, so tests can assert plaintext never appears in an event and that encryption was to the **own** pubkey.

## Assumptions and decisions

1. **`hyper://` grammar** — `hyper://<core-key-hex64>/<blockOffset>-<blockLength>[+<byteOffset>]`, `byteLength` = imeta `size`. This is what the fixtures encode (`hyper://<hex>/0-<blockLength>`). `contracts/manifest.ts` describes `hyperUrl` as z32; **z32 is not accepted** (the `z32` package is only a transitive dep, and I did not want to add one). If L2/L6 settle on z32, `hyper-url.ts` is the single place to change.
2. **Extra imeta keys** (not in NIP-92/94/71): `image-x <sha256>` (thumbnail hash, needed for T16 — the fixtures carry `image.sha256` but the plan's imeta line has nowhere to put it), `label`, `bitrate` (bits/s per NIP-71), `placeholder` (data URL), `caption <lang> <url> [sha]`, `storyboard <url> <cols> <rows> <interval> [sha]`; top-level `block_size` only when ≠ 64 KiB. Parse ignores unknown keys. Fixture `Rendition.placeholder` / `image.sha256` are not in the fixture's own `event.tags`, so a fixture-event → manifest parse cannot be strict-equal to the fixture manifest; the required direction (manifest → build → parse) is.
3. **Required tags** for a manifest: `title`, ≥1 `imeta` (each needs `url` (hyper), `m`, `x`, `size`), ≥1 `mint`, `price`, `p2pk`. `published_at` falls back to `created_at`; `split` defaults 50/50; `duration`, `t`, `blossom` optional.
4. **Comments on videos use `E`/`e`**, not `A`/`a`: kinds 21/22 are regular events and NIP-22 reserves `A` for addressable ones; build-plan §2.2's wording and the mock's `["A", "21:<id>"]` are the deviation. `parseComment` reads that legacy `A` shape leniently, but `fetchComments` filters on `#E`, so mock-shaped comments on a real relay would not be found. Worth aligning `mocks/fixtures.ts` with the orchestrator.
5. **`queryOne` uses `limit: 1`.** A relay that serves a forged "newer" replaceable event under `limit: 1` hides the genuine one; the forged one is dropped and the caller gets `null` (tests assert exactly this). Over-fetching would not defeat a relay that simply withholds, so I kept it honest and simple.
6. **Trending amounts are relay-claimed** (`proof` tag `amount`s), not DLEQ/P2PK-verified — that is the payment lane's job. Only `unit: sat` (or absent) counts; one payer = one "paid view".
7. **NIP-05 normalisation**: identifiers are lower-cased before the strict `a-z0-9-_.` check; `lookupNip05` ignores redirects (`redirect: 'manual'`, non-200 = fail) per the spec's security constraint. `nostr-tools/nip05` is not used because its `useFetchImplementation` is module-global.
8. **`FakeRelayPool` orders injected junk by its claimed `created_at`**, as a real relay would, so tamper tests are realistic.
9. `SimplePoolAdapter` re-verifies events that `SimplePool` already verified (through the boundary). Cost is one Schnorr verify per event; the fresh-copy design deliberately discards the library's cached verdict.
10. Private-set `isPrivate` on a `Playlist` is inferred from "no public `e` tags and non-empty content"; an emptied private playlist reads as public-with-no-videos. Cosmetic; flag if the UI cares.

## Things I was unsure about

- Whether "subscriptions" should also write kind 3. I write only the kind-30000 `channels` set (plan's recommendation) and read kind 3 as a fallback.
- `history`'s item shape is my own (`["watched", id, positionSec, at]`); NIP-51 leaves private item shapes open. Only this layer reads them.
- `NutzapInfo` for x-only `pubkey` values: I prefix `02` (NIP-61 says clients MUST lock to the `02`-prefixed key). If a creator publishes a `03…` key it is kept as-is.
- Live subscriptions keep an in-memory `seen` id set for dedupe; unbounded for very long sessions.

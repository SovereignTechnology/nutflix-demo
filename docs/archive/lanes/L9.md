## The MDWE finding (build-plan §7 "test MemoryDenyWriteExecute against the JS engine's JIT")

Empirical, user scope (`systemd-run --user --wait -p MemoryDenyWriteExecute=yes`), Node v22.22.0, systemd 255:

- **Default JIT: aborts at startup**, even for `node -e 'console.log(1)'` — `V8_Fatal` in `OS::SetPermissions` ("Check failed: 12 == errno": V8 tolerates only `ENOMEM` when making a code page executable; MDWE returns `EACCES`). Not a tier-up race; there is no workload shape that survives.
- **`--jitless`: survives**, including `sodium-native` (`sodium_malloc`, `mprotect`, `mlock` all work), `udx-native`, `rocksdb-native` via Corestore, `http`, `worker_threads`, and a full `HyperDHT` bring-up under the whole seccomp set.
- Cost: `@noble/curves` secp256k1 verify (the DLEQ path) 1.27 → 2.11 ms (**1.66×**); native hashing unaffected; **`WebAssembly` is removed entirely** (nothing on the server path uses it; `nostr-wasm` is opt-in).
- **Decision:** both units ship `MemoryDenyWriteExecute=yes` + `ExecStart=node --jitless …`, documented as a pair that must be changed together.
- **Second finding:** the plan's literal `RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX` makes `hyperdht` **throw `EAFNOSUPPORT` in its constructor** (`dht-rpc` → `udx.watchNetworkInterfaces()` → `getifaddrs` → `NETLINK_ROUTE`). The units add `AF_NETLINK`. Verified both ways.

Full tables in `deploy/systemd/MDWE-RESULTS.md`.

## Assumptions

- **Event kind 30063** for the release notice, `d`=`nutflix-web`, `x`=sha256 tree hash. Not in the frozen contracts → `docs/contract-requests/L9.md`. `--kind` overrides.
- **Native inventory is per-platform** (linux-x64 = CI image + deploy target). `--check` on another platform warns and exits 0 unless `NATIVE_INVENTORY_STRICT=1`; CI sets it. This is not a weakening: the old script had the same platform dependence silently.
- **`ExecStart` lines** assume `node --jitless <package main> --config /etc/nutflix/<svc>.json`; the flags are L2's/L3's to confirm. `/usr/bin/node` ≥ 22.
- **CSP defaults** allow only `'self'` (+ `blob:` for img/media, for verified Blossom blobs and MSE); L7 must pass relay/gateway origins explicitly with `--connect` — the tool refuses to guess third parties.
- **Local `npm run ci` is offline**; `npm audit signatures`, `npm audit`, lockfile re-resolution and the provenance report run only in CI (they need the registry).
- `tsc -b` for the scripts tests uses `composite: true` + `noEmit: true` (accepted by TS 6.0.3; only a gitignored `tsconfig.scripts.tsbuildinfo` is produced).

## Unsure / worth a second look

- `hyperswarm` and `nostr-tools` — two of the eleven direct runtime deps — publish **no provenance**. Nothing to do locally; flagged for the bump reviewer.
- The Electron lint is a text scanner (no parser dependency). It handles object literals, options-object variables (`new BrowserWindow(opts)` in a file that has a literal `webPreferences`), comments and strings; it cannot follow a `webPreferences` object imported from another module and reports that as a failure, which is the conservative direction.
- The CSP/SRI rewriter is regex-based: attribute values containing `>` and `<script>` inside `<template>` are edge cases it does not model. It masks HTML comments, so a commented-out script is neither rewritten nor reported.
- `npm audit --audit-level=high` in CI is blocking; a freshly published advisory will fail unrelated MRs. That is the intended posture, but it is a judgment call the orchestrator may want to soften to `allow_failure`.
- `deploy/systemd/test-hardening.sh` can only run where a user systemd instance exists — not in the container CI job. It should be rerun on a real host on every Node major bump.
- No `PrivateUsers=`, `DynamicUser=`, `LoadCredentialEncrypted=` in the units — reasons in the README; all three deserve a look once L2's key-at-rest format exists.

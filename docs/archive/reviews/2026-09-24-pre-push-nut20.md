## Adversarial questions

- **Who can mint a paid quote.**
  - Locked: only the holder of the wallet key.
    - Proven by the test mint, which refuses a missing or wrong signature with 20008.
    - Proven on Nutshell 0.21.0 and cdk-mintd 0.18.1 (`real-mint.integration.test.ts` F17: one
      `POST /v1/mint/bolt11`, so the amended signature is accepted first try).
  - Unlocked (a mint without NUT-20, or a signer-held key): still bearer. Its id no longer reaches
    the desktop renderer.
- **A mint that ignores the lock.**
  - `mintQuote` refuses an answer whose `pubkey` is not ours (`bad-mint-response`, tested).
  - A mint that later answers "unlocked" for a quote we locked only hurts itself: the ecash is
    minted into our wallet either way, and the mint is trusted for issuance anyway.
- **A quote locked to someone else's key.** `Spender.mint` refuses before any request
  (`invalid-argument`, tested). A malicious mint therefore cannot make the wallet sign for a key
  it does not hold.
- **The key as a string.**
  - cashu-ts signs NUT-20 itself and takes the private key as hex. A JS string cannot be wiped.
  - `withSecretHex` lends it to that one call only.
  - Only an in-process key (`memoryWalletKey`, the NIP-60 wallet key already decrypted into a
    `Uint8Array`) offers it. A signer-held key (the seeder's `LocalSigner` wallet key) does not,
    and that wallet takes unlocked quotes.
  - The seeder never mints quotes today.
  - The desktop's `LocalSigner` holds no wallet key, so its NIP-60 wallet locks.
- **`"pubkey": null`.** Nutshell answers an unlocked quote with `null`. Only a non-empty string
  counts as a lock (real-mint tested).
- **Renderer: forging a handle.**
  - An unknown or raw quote id answers `not-found` (tested).
  - The renderer's `mint` and `amount` are ignored: the stored quote is polled (tested).
  - A handle is 128 random bits.
- **Renderer: leak through events.**
  - `wallet.change` quote events are translated to the same stable handle (tested: no output
    carries the real id in a `quoteId` field; the mutation that emits raw events fails).
  - Melt quote ids still pass: they are not bearer, since a melt spends our own proofs.
- **Signer change.**
  - Found in review, fixed before commit: without scoping, a handle issued for identity A could
    be polled after a switch to identity B, and B's wallet would mint A's unlocked quote.
    `SwitchingWallet.generation()` now scopes handles. A swap forgets every handle, and a quote
    still being made across a swap is refused (tested; both mutations fail the test).
- **Memory.** 256 handles at most; the oldest is forgotten first (tested).

## Found and fixed before commit

- Handles outlived a signer change (above).

## Residual

- [Low] A signer-held wallet key takes unlocked quotes. That needs cashu-ts to accept a signing
  callback for NUT-20, or a `Signer` method over the amended message.
- Quote handles live in the host process. A host restart forgets them, and the renderer's Fund
  sheet then sees `not-found` for an open invoice. The core wallet's `pendingMintQuotes` still
  knows the quote, but it is not wired to a UI.

## Also on this branch: the daemon's relay pool at shutdown

CI surfaced an uncaught `WebSocket was closed before the connection was established`, raised
while the gateway CLI test shut down. nostr-tools clears a socket's `onerror` before closing it.
`ws` then emits the abort of a still-connecting handshake as an `'error'` event with no listener,
so Node throws it and a daemon stopping mid-connect dies.

The fix: `createRelayPool` gives nostr-tools a `ws` subclass that has an `'error'` listener from
birth. The listener hides nothing: nostr-tools' own `onerror` is a separate listener.

Test: `seeder/src/__tests__/relay-pool.test.ts`, with a relay that accepts TCP and never answers
the upgrade. It fails with the plain `ws` class.

The desktop host's pools use Node's global (undici) WebSocket, an `EventTarget` that never
throws, so they are not affected.
